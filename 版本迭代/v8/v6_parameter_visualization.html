v6 训练参数建议可视化

目标：优先保证训练稳定、可收敛、不过拟合，再逐步提升模型容量。以下建议是基于 v6 的自适应温度与多主题版本特征整理的训练侧调参参考。

学习率 learning_rate

最高优先级
推荐起点3e-4
常用范围：1e-4 ~ 1e-3
  • 过大：loss 波动，训练不稳定。
  • 过小：收敛慢，模型学得保守。
  • 优先观察验证集 loss 的趋势。

Batch size

稳定性
推荐起点16 / 32
常用范围：16 ~ 64
  • 越大越稳，但更吃显存。
  • 越小噪声越大，可能更不稳。
  • 显存允许时优先尝试 32。

Epochs

收敛程度
建议看验证集早停
不是固定越多越好，建议配合验证集监控。
  • 验证 loss 持续下降：继续训。
  • 验证 loss 上升：可能过拟合。
  • 可考虑保存最优 checkpoint。

Dropout

防过拟合
推荐起点0.1 ~ 0.2
常用范围：0.1 ~ 0.3
  • 过低：容易记住训练集。
  • 过高：模型学不充分，输出发虚。
  • 数据量偏小时通常更需要 dropout。

block_size

上下文长度
推荐起点128
常用范围：64 / 128 / 256
  • 更大：上下文更完整，但更慢更吃显存。
  • 更小：训练快，但可能只会局部搭配。
  • 古诗任务通常 128 是较稳的起点。

d_model

模型宽度
推荐起点256
常用范围：256 ~ 512
  • 越大，表达能力越强。
  • 也会带来更高训练成本。
  • 资源有限时先用 256。

n_head

注意力头
推荐起点4 / 8
常用范围：4 ~ 8
  • 头数增加能看到不同层面的关联。
  • 与 d_model 一起配合设置更合理。

n_layer

模型深度
推荐起点4 / 6
常用范围：4 ~ 8
  • 层数越多，建模能力更强。
  • 但训练难度、过拟合风险也会上升。

推荐组合方案

可直接试
方案 参数组合 适用场景
稳妥版 lr=3e-4, batch=16/32, epoch=20~40, dropout=0.1, d_model=256, n_head=4, n_layer=4, block_size=128 先跑通、看是否稳定收敛
增强版 lr=1e-4~3e-4, batch=32, epoch=30~60, dropout=0.1~0.2, d_model=512, n_head=8, n_layer=6, block_size=256 显存和训练时间更充足时
轻量版 lr=5e-4, batch=16, epoch=15~30, dropout=0.2, d_model=128/256, n_head=4, n_layer=4, block_size=64/128 资源有限、先快速试错
调参顺序建议：先调 learning_rate，再调 batch_size 和 dropout，然后看 block_size，最后再考虑扩大 d_model / n_head / n_layer。
如果训练集很好但验证集差，优先降低模型容量或提高 dropout；如果 loss 一直降不下来，优先检查学习率是否过小。
