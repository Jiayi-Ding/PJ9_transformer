block_size ：32	   64		128		256		512

发现，随着 block_size 的逐渐增大，验证集损失（val loss）和训练集损失（train loss）的收敛下限均呈现出先降低后趋于平稳的倒 U 型演进趋势。具体表现为：当 block_size 从 32 增大到 128 时，五言的最低 val loss 从 4.10 显著下探至 4.03 附近，七言从 4.41 下探至 4.31 附近。然而，当 block_size 进一步拓宽至 256 甚至 512 时，两条损失曲线的下限值几乎不再发生明显位移。此外，在所有空间跨度下，模型直到第 6 个 Epoch 结束依然表现出平稳收敛特征，未触发过拟合抬头。

初步结论：增大 block_size 能直接拓宽自注意力机制（Self-Attention）的时序感受野，赋予模型更强的长程上下文建模能力，这对于捕获古典诗歌内部跨句的押韵、对仗以及整体章法结构具有关键性的助益（这解释了小窗口如 32、64 时损失普遍偏高、无法彻底收敛的现象）。但当 block_size 超越特定临界点（如 128）后，由于单首诗歌的实际 Token 长度本身有限，更长的语义窗口无法提供更多增量信息，增益表现出明显的边际效应递减，反而会线性增加非必要的计算显存负担。

权衡 “保障长程韵律建模能力” 和 “避免信息冗余及计算资源浪费” 两个因素，认为上述参数组合下，block_size = 128 是最优参数，这恰好也是我们的基准参数。
